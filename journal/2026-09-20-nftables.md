# 2026-09-20 — Pose du pare-feu nftables de base

**Demande :** appliquer le ruleset corrigé du TP 1 et rendre le pare-feu permanent. Le mode maintenance reste à faire en TP.

## Constats avant de commencer

- Le ruleset était **vide** (flush ou reboot depuis le TP).
- **Aucune route IPv4 par défaut** (`ip route` sans `default via`). Toute la sortie Internet — NTP, apt, la session Claude elle-même — passe en **IPv6** grâce aux RA de la Freebox. Cause : `gateway4: 10.0.0.1` dans netplan.
- Résolveur DNS réellement utilisé : `fd0f:ee:b0::1` (Freebox, IPv6 ULA). Les 8.8.8.8 / 1.1.1.1 déclarés sont injoignables sans route v4.
- La session Claude (`ccd-cli`) est connectée en IPv6 vers `2607:6bc0::10:443` → **un `policy drop` en sortie sans 443 la coupe**.

## Procédure suivie

1. Filet de sécurité : `systemd-run --on-active=240 --unit=fw-rollback nft flush ruleset`.
2. Écriture de `/etc/nftables.conf` ([copie](../config/nftables.conf)) : ruleset corrigé + DNS IPv6 + `include "/etc/nftables.d/*.nft"` en fin de fichier. Ancien fichier sauvegardé en `.bak-*`.
3. `nft -c -f` (syntaxe OK), puis `nft -f`, **et dans la même commande** ajout de deux règles en mémoire ouvrant 80/443 hors LAN (v4 et v6), commentées `TEMP-claude-session`.
4. Les règles TEMP ayant été ajoutées après le `log`, repositionnement avant (`nft insert rule … position <handle>`).
5. Tests :
   | Test | Résultat |
   |---|---|
   | `getent hosts archive.ubuntu.com` | résout (via `fd0f:ee:b0::1`) |
   | `curl -sI https://archive.ubuntu.com` | 200 OK |
   | `nc -zv 192.168.1.50 22` | **bloqué**, ligne `OUT-DROP … DPT=22` dans dmesg |
   | `nc -zv 192.168.1.35 5044` | délai dépassé, mais **pas** de OUT-DROP → la règle passe, la VM ELK est éteinte |
   | `ping 192.168.1.254` | OK |
6. Filet désarmé, `systemctl enable nftables`.
7. **Incident instructif :** `systemctl start nftables` a rechargé le fichier (`flush ruleset` en tête) et **effacé les règles TEMP**. La session Claude n'a survécu que par `ct state established`. Règles remises aussitôt. → Leçon : tout ce qui doit survivre vit dans un fichier lu par le service. C'est le point de départ du TP 2.
